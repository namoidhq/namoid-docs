---
title: Next.js SDK
description: Use @namoidhq/nextjs for a server-side NamoID Auth transaction in the Next.js App Router.
---

`@namoidhq/nextjs` implements the confidential NamoID Auth flow for the Next.js
App Router. It stores short-lived transaction state in `HttpOnly` cookies,
exchanges the callback code with an Auth secret key, and validates the returned
access token. This guide requires version 1.1.0 or later.

## Install

```bash
pnpm add @namoidhq/nextjs @namoidhq/js
```

## Configure the client

```ts
// lib/namoid.ts
import { createNamoIDNextClient } from "@namoidhq/nextjs";

function required(name: string): string {
  const value = process.env[name];
  if (!value) throw new Error(`${name} is required`);
  return value;
}

export function getNamoID() {
  return createNamoIDNextClient({
    authSecretKey: required("NAMOID_AUTH_SECRET_KEY"),
    appBaseUrl: process.env.NEXT_PUBLIC_APP_URL ?? "http://localhost:3000",
    apiBaseUrl: process.env.NAMOID_API_BASE_URL,
    callbackPath: "/api/auth/callback/namoid",
    postLoginRedirectPath: "/dashboard",
    postLogoutRedirectPath: "/login",
  });
}
```

```bash
NAMOID_AUTH_SECRET_KEY=namoid_auth_sk_test_…
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

The secret key resolves the application, environment, and Hosted Auth domain.
Do not add an application ID, issuer, or Hosted Auth URL. Keep client creation
inside `getNamoID()` so a production build can finish before runtime secrets are
injected.

The defaults are:

- callback path: `/api/auth/callback/namoid`
- post-login path: `/`
- post-logout path: `/login`
- transaction lifetime: 10 minutes

Optional settings include `apiBaseUrl`, `callbackPath`, `cookiePrefix`,
`transactionMaxAgeSeconds`, and a custom `fetcher`.

## Login route

```ts
// app/api/auth/login/route.ts
import { getNamoID } from "@/lib/namoid";

export async function GET() {
  return getNamoID().login({ returnTo: "/dashboard" });
}
```

Pass `mode: "sign_up"` or `mode: "waitlist"` to start another NamoID Auth
page. `returnTo` must be a relative application path.

## Callback route

```ts
// app/api/auth/callback/namoid/route.ts
import { getNamoID } from "@/lib/namoid";

export async function GET(request: Request) {
  return getNamoID().callback(request, {
    async onSuccess({ tokens, transaction }) {
      // Store tokens in your server-side session here.
      // transaction.returnTo is validated as a relative path.
      return Response.redirect(
        new URL(transaction.returnTo, request.url),
        302,
      );
    },
    async onError(error) {
      console.error(error);
      return Response.redirect(
        new URL("/login?error=auth", request.url),
        302,
      );
    },
  });
}
```

Without `onSuccess`, the SDK redirects to the transaction's `returnTo`. Without
`onError`, it redirects to the configured post-logout path with an error query
parameter.

## Logout route

```ts
// app/api/auth/logout/route.ts
import { getNamoID } from "@/lib/namoid";

export async function POST() {
  const session = await readYourServerSession();

  return getNamoID().logout({
    accessToken: session?.accessToken,
    refreshToken: session?.refreshToken,
  });
}
```

When an access token is supplied, the SDK revokes the native session. It then
redirects through the environment's `/sign-out` page to clear the hosted
browser session. Set `clearHostedSession: false` when only the local application
session should end.

## Security notes

- Keep `authSecretKey` server-side.
- Use an application Auth secret key from the same Test or Live environment as
  the Hosted Auth configuration you intend to use.
- Store returned tokens in a server-side session, not browser storage.
- The SDK's transaction cookies are `HttpOnly`, `SameSite=Lax`, and `Secure`
  whenever `appBaseUrl` uses HTTPS.
- Create the configured callback URL in the environment's NamoID Auth settings.
